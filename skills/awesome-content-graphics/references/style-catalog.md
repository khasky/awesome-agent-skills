# Style catalog — the archetypes a post graphic can be

`visual-language.md` answers "what shape draws this idea". This file answers the question before it: **what kind of picture is this at all.** A run that only ever produces one accent shape on an empty field has one idea of what a post graphic is, and a gallery of twenty of them looks like twenty of the same thing.

The catalog is built from a corpus of graphics that work in real feeds: developer-tool announcements, infographic posters, product banners, meme panels and editorial quote cards. What follows is what they have in common, taken apart into axes that combine, then reassembled as archetypes that can be asked for by name.

## The five axes

Any graphic in the corpus is a point in this space. Varying one axis while holding the others is what makes a set of twenty read as twenty.

**1. Density — how much the canvas is asked to carry.** This is the axis that matters most and the one a timid run never leaves.

| Level | Type on canvas | Reads as |
| --- | --- | --- |
| **Bare** | one headline | a statement |
| **Anchored** | headline, subhead, one object | a claim with evidence |
| **Structured** | headline plus 2 to 4 labelled groups | an explanation |
| **Dense** | headline plus 6 or more labelled cells | a poster, a reference sheet |

**2. Surface — what the picture is printed on.** Deep dark with an off-canvas light and a vignette. Near-white with a pastel wash in the corners. Warm paper, cream or bone. A saturated gradient field running corner to corner. An aged, grained, foil-on-black print. The surface sets the mood before a word is read, and it is the cheapest axis to vary.

**3. Typography as image.** Type is not always a caption on a picture; sometimes it *is* the picture. Solid heavy caps filling the canvas edge to edge. The same caps as outlines with the surface showing through. Editorial serif set at quotation size. A phrase sitting on a highlighter slab. A headline where exactly one word takes the accent colour and the rest stay ink.

**4. The proof object — the thing that shows this is real.** A terminal with real commands in it. An editor window with syntax colour. Browser chrome around a page. A chat thread. A commit list. A row of skeleton bars standing in for text nobody needs to read. An emoji or icon rendered large enough to be the subject.

**5. Atmosphere — the layer that separates a designed image from a diagram.** A field of faint symbols scattered behind everything at low alpha. Bloom behind the subject. A vignette pulling the corners down. Cards fanned behind the main card. Grain over the whole print. Each of these is optional and each one, added alone, is the difference between flat and finished.

## The archetypes

Twelve. Each names its density, its type budget and the failure that kills it.

### 1. Statement

One line, huge, on an almost empty canvas. The subhead is optional and small. Nothing else competes.

- **Type budget:** headline, optional subhead, optional wordmark.
- **Layout:** headline left-aligned on the upper third, or centred with deep margins. 45 to 60 percent of the canvas stays empty on purpose.
- **Devices:** vignette, off-canvas light, bloom, a single oversized glyph opposite the text.
- **Fails when:** the line is a topic instead of a claim. With nothing else on the canvas there is nothing to carry a weak sentence.

### 2. Statement with a proof object

The canvas splits: claim on one side, an artifact on the other that proves the claim is about something real. This is the workhorse of developer-tool marketing and the highest-value archetype the corpus contains, because it is the only one that shows the thing rather than describing it.

- **Type budget:** headline, subhead, plus whatever real text lives inside the object (commands, code, UI labels).
- **Layout:** text block on 40 percent, object bleeding off the opposite edge on 60. The object is cropped by the canvas edge rather than floating fully inside it.
- **Devices:** UI chrome, syntax colour, a chip row under the subhead, a second card fanned behind the first, atmosphere field behind both.
- **Fails when:** the object is decorative — a generic code window whose contents say nothing. Whatever is inside it has to be the real command, the real output, the real screen.

### 3. Split compare

Two panels, one per option, built to the same template so the differences are the only thing the eye finds. Sometimes a third strip underneath collapses the comparison into one line.

- **Type budget:** headline, two panel titles, up to 4 short bullets per panel, one summary line.
- **Layout:** equal halves with a visible gutter; each panel gets its own accent hue, and those two hues are the only colours in play.
- **Devices:** an icon per panel, a rule under each panel title, a summary strip in a third colour at the bottom.
- **Fails when:** the two panels are not truly parallel — different bullet counts, different lengths, one panel with an extra element. Parallelism is the whole mechanism.

### 4. Chain

A row of nodes connected left to right: the steps of a process, the stages of a pipeline, a before and after with an arrow between them.

- **Type budget:** headline, one word or short phrase under each node, up to 6 nodes.
- **Layout:** nodes on one horizontal axis, evenly spaced, connectors thinner and more recessive than the nodes.
- **Devices:** circular node plates, an icon or emoji inside each, a dashed connector for a step that is optional or automatic, the final node in the accent.
- **Fails when:** it runs past 6 nodes, or the labels grow into sentences. A chain is a rhythm; sentences break it.

### 5. Poster

A whole system on one canvas: a masthead, a manifesto column, 4 to 6 numbered sections each with its own icons and takeaway, and a footer with the next step. This is the archetype that gets saved and re-shared, and the one that takes the most work.

- **Type budget:** deliberately large, but strictly tiered — masthead, section numbers, section titles, item labels, one takeaway line per section, footer. Six levels, and every word belongs to one of them.
- **Layout:** a left column carrying the manifesto in oversized type, a right grid of numbered blocks, a full-width footer. The left column is what forces the read order.
- **Devices:** grain, foil or metallic accents, letterpress-style caps, ruled dividers, a star or diamond ornament repeated at fixed positions, a bordered footer.
- **Fails when:** every block has equal weight, so the eye has no entry point; or when it is read at thumbnail size, where it becomes texture. A poster is for the feed's tap-through, not for the scroll.

### 6. Catalog grid

Rows of categories, each row a strip of small labelled cells. The subject is the count and the coverage, not any single cell.

- **Type budget:** title, a category label per row, a name under each cell.
- **Layout:** a coloured category card at the left of each row, cells in a uniform strip to its right, ragged right edge where a category has fewer entries. That ragged edge is honest and looks better than padding the rows out.
- **Devices:** one hue per category on the left card only, cells kept neutral so the grid does not turn into confetti.
- **Fails when:** the cells need logos that have to be fetched. Offline, a cell is a letterform, a simple drawn mark or an emoji, and nothing else.

### 7. Transcript

A conversation, rendered as the interface it happened in: chat bubbles, a message thread, a commit log, a terminal session.

- **Type budget:** the lines themselves, plus an optional wordmark. Often no headline at all, because the last line *is* the headline.
- **Layout:** two bubbles are usually enough, one in from the left and one in from the right, with the punchline on the right in the accent.
- **Devices:** a gradient fill on the reply bubble, a monospace face for anything from a terminal, a faint wordmark bottom-right.
- **Fails when:** the transcript is invented. A fabricated user quote is a fabricated testimonial with a rounded rectangle around it.

### 8. Strip

Two or three panels in a row, each with a bordered frame, a speech bubble and one image. A setup, a beat, a payoff.

- **Type budget:** one short bubble per panel; the last panel may carry a product line instead.
- **Layout:** equal panels, thick dark borders, a different flat background per panel, the final panel switching to a saturated fill so the payoff reads instantly.
- **Devices:** rounded speech bubbles with a heavy stroke, an oversized emoji as the character, a paper-coloured gutter between frames.
- **Fails when:** it needs drawn characters. With emoji as the cast it works offline; with anything more it does not.

### 9. Cut paper

Every word set in heavy caps on its own rectangle, each rectangle a different flat colour and rotated a couple of degrees, assembled into a headline. Loud, cheap to render, and it never looks machine-made.

- **Type budget:** the headline only, plus one small line of metadata underneath.
- **Layout:** blocks flowing across two or three lines, overlapping slightly, rotations alternating in sign and staying under 4 degrees.
- **Devices:** a drop shadow per block so they sit above the surface, one block in the accent taking the key word.
- **Fails when:** the rotations are uniform, or the colours are all from the same family. Its whole appeal is that it looks assembled by hand.

### 10. Emphasis diagram

The abstract composition: one accent form against a de-emphasis field, sized to the real values. This is what `visual-language.md`'s shape table draws, and it stays the right answer whenever the idea is a relationship rather than a thing.

- **Type budget:** headline only. No labels, no legend, no values on marks.
- **Fails when:** it acquires an axis label and becomes a chart nobody asked for.

### 11. Annotated scene

An illustrated or photographic scene with callouts pointing into it: an environment, a character, a situation, with hand-lettered labels naming what is wrong or what is happening.

- **Feasibility:** **this one cannot be rendered offline.** A scene needs an illustrator or an image model, and this skill has neither. What *is* reachable is the annotation layer over an abstract composition: curved dashed leader lines, small callout labels, a split canvas with a cool half and a warm half, a caption bar across the bottom. Offer the annotation devices, and say plainly that the illustrated scene is out of scope rather than producing a thin imitation of it.
- **Fails when:** attempted anyway. A flat approximation of an illustration looks like a failed illustration; the abstract composition it should have been looks deliberate.

### 12. Meme two-panel

Top panel and bottom panel, the same subject in two states, a hard caption band across each. Day one and day thirty. Expectation and reality.

- **Type budget:** two caption bands, plus scattered small labels in the second panel naming what went wrong.
- **Feasibility:** same limit as the scene above when it needs drawn characters. It works offline when the two states are abstract compositions or UI states rather than people.
- **Fails when:** the joke needs a face. Offline, the two panels have to carry it structurally.

## Picking archetypes for a set

**Spread the set across archetypes, not just across shapes.** A gallery whose twenty entries are twenty emphasis diagrams asks the user to choose between twenty near-neighbours; a gallery carrying a statement, three proof-object variants, two splits, a chain, a poster, a transcript and six diagrams asks a real question.

- At least **⌈n / 5⌉ distinct archetypes** in a set of n, and no single archetype taking more than **40 percent** of it.
- Weight toward what the idea actually is. A mechanism wants diagrams and chains; a capability with a visible interface wants proof objects; a comparison wants splits; an opinion or a quotable line wants statements and cut paper.
- **The poster is worth exactly one slot when the source can fill it.** It is the most expensive variant to build and the one most likely to be picked, so build it once and build it properly rather than twice cheaply.
- Where the user pinned an archetype in the look inputs, the set is that archetype at several densities and surfaces, and the spread rule is waived — they answered the question the spread exists to ask.

## Device library

Cross-cutting, and all of them renderable offline with CSS and inline SVG.

| Device | What it is | Notes |
| --- | --- | --- |
| **Atmosphere field** | 15 to 30 faint symbols scattered behind everything at 4 to 10 percent alpha, varied in size and rotation, some blurred | The single highest-yield addition to a flat canvas. Deterministic placement per `visual-language.md`, never random |
| **Vignette** | A radial darkening pulling the corners down 20 to 40 percent | Makes a dark surface read as lit rather than as flat black |
| **Bloom** | A soft glow behind the subject in the accent, larger and softer than the subject itself | Two layers, a tight one and a wide one, reads better than one |
| **UI chrome** | Browser bar with traffic-light dots, a terminal titlebar, an editor tab strip | Draw it, never screenshot it. The contents must be real |
| **Skeleton bars** | Rounded bars at uneven widths standing in for text | Says "content" without spending words |
| **Highlight slab** | A translucent or solid rectangle behind one phrase of the headline | The cheapest way to make a headline point at its own key phrase |
| **Two-tone headline** | One word in the accent, the rest in ink | Works when the accented word is the claim's verb or its subject, not an adjective |
| **Big numeral** | A number set two to three times the headline size, treated as a shape | Only when the number is the point |
| **Chip row** | Small bordered pills carrying short labels under the subhead | Caps at 4. Five chips is a list pretending to be a badge row |
| **Fanned cards** | Two or three cards rotated a few degrees behind the main one | Gives depth without blur |
| **Node and connector** | Circular plates joined by thin lines, dashed where the step is automatic | The chain archetype's whole vocabulary |
| **Emoji as artwork** | A system emoji rendered at 200 to 500 px as the subject or the cast | Available offline from the system emoji font, no asset needed |
| **Callout leader** | A curved dashed line from a small label into the composition, with a small arrowhead | Reads as annotation. Keep to 3 or fewer per canvas |
| **Grain** | A tiled noise overlay at 3 to 8 percent | Turns a flat print into a printed one. Generate as an inline SVG turbulence filter, never as a fetched texture |
| **Rule and ornament** | Hairline dividers, a small repeated diamond or star at fixed positions | The poster's connective tissue |

## What the words on the canvas are allowed to be

The old rule was one headline and nothing else, which rules out eight of the twelve archetypes above. The rule that replaces it is not looser about quality, only about quantity:

**Every word on the canvas does one of five jobs.** It is the headline that carries the claim. It is a label naming a real thing the picture depicts — a command, a filename, a UI element, a step. It is a value that is itself the point. It is a takeaway line closing a section of a dense archetype. Or it is the wordmark. **A word doing none of those is decoration, and it is cut.**

Three consequences that keep density from becoming a slide:

- **The archetype declares the budget and the budget is not exceeded.** A statement that grows a caption has become an anchored graphic badly; either commit to the denser archetype or cut back to the bare one.
- **Read order is forced, always.** One element is unmistakably first: by size, by position, by being the only thing in the accent. A dense canvas where six blocks have equal weight has no entry point, and the eye leaves.
- **No orphan label.** A word on the canvas that names something the picture does not show, or that only makes sense to a reader who has already read the post, is cut. This is the check that used to be enforced by banning labels outright.

## Honesty rules that scale with density

The denser archetypes can assert far more than a single shape can, so the fidelity rules bind harder rather than softer:

- **A depicted interface shows real behaviour.** A terminal shows a command that works, an editor shows code that runs, a product screen shows what the product does. A mocked-up third-party interface showing a behaviour it does not have is a fabricated screenshot whether or not it is drawn by hand.
- **A transcript is real or it is not shown.** Invented user messages, invented reviews, invented counts under a reaction bar: all fabricated testimonial.
- **No third-party logo the sources do not connect to the subject** — and offline there is nothing to fetch anyway, so a logo is either a simple mark drawn from scratch for something the post genuinely is about, or it is absent.
- **Numbers on the canvas come from the facts, with the condition they carry.** A big numeral is the loudest claim the format has.
- **No calendar date, no "checked on" stamp**, in any archetype.
- **No trademark word carrying its ordinary meaning**, headline or label alike.

## Feasibility, stated plainly

Everything in this catalog renders offline from HTML, CSS and inline SVG with system fonts — **except** photographic scenes, illustrated characters and anything needing a fetched brand asset or a display font that is not installed. Where the user's reference is one of those, say so rather than shipping an approximation: the honest answer is the nearest archetype that *is* reachable, named as a substitution, plus the note that a scene needs an illustrator or an image model this skill deliberately does not call.

Fonts are the quiet version of the same limit. A western letterpress poster, a handwriting callout and a condensed grotesque are three different faces, and offline there is one system stack. Weight, letter-spacing, case and outline treatment are the levers that remain; use them, and do not describe a variant as a style the installed fonts cannot set.
