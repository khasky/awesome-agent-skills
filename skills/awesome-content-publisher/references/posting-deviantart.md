# deviantart

Check: `deviantart.com/studio/journals` signed in shows `Post a journal` with `Start a Draft`, and the Studio navigation with `Drafts`, `Published` and `Scheduled`; the profile is `deviantart.com/<handle>`.

Compose: `Start a Draft` opens the `Submit a journal` dialog: `Who can see it?` (left on its default), `Add Cover Image`, the title textbox (`Add your title here`, with a read-time estimate beside it), the rich body (`Start typing your main text here, or begin by adding an image or video.`) with a formatting toolbar and block menu, a `Featured Post` toggle, then `Save to Studio` (draft) and `Submit`. Tags are a control inside the same dialog and come from the post file's `hashtags`. Classify the editor before typing: check whether a `## ` line converts, and use the toolbar for headings and links when it does not. An interrupted run leaves a draft under `Drafts`.

Read-back: `deviantart.com/<handle>/journal`, newest entry; confirm the title, the cover and the headings.

The journal editor is TipTap, and it hands you its own `Editor` instance. The body node is `.tiptap.ProseMirror[contenteditable="true"]`, and that DOM element carries an `editor` property — the live TipTap instance, with `editor.schema`, `editor.state`, `editor.view` and the whole `editor.commands` surface. Read the schema before deciding how to insert anything: this one has nodes `paragraph heading blockquote bulletList orderedList listItem hardBreak horizontalRule anchor` plus DeviantArt's own `da-emote da-gif da-video da-deviation da-gallery da-mention da-deviation-thumb`, and marks `link textStyle bold italic strike underline da-hashtag`. There is no `codeBlock` node and no `code` mark, so every `<pre>` and every `<code>` in a pasted document is silently flattened into a paragraph. Synthetic paste of `text/html` into the focused node works normally otherwise — headings, lists and paragraphs all survive.

Two consequences follow from the missing code nodes, and both need repairing after the paste. Flattened command blocks read as body prose, and the nearest thing the schema offers is `blockquote`: find each command paragraph by the text it starts with, `setTextSelection` just inside it and `wrapIn('blockquote')`, which renders as a ruled block distinct from the surrounding text. And with the code container gone, the Link extension autolinks every URL it now sees in plain text — including the ones inside commands, which is the defect `awesome-content-repurpose` warns about. Walk `editor.state.doc.descendants`, collect the text nodes carrying a `link` mark whose `href` is not one of the post's real reference links, and `removeMark` them in one transaction. Verify after: `pre a` count is meaningless here (there are no `pre` nodes), so the check is the anchor list itself — it must hold exactly the reference URLs and nothing from a command.

The cover image goes through a Sta.sh picker, and the picker's hidden inputs take the file directly. `Add Cover Image` (top right of the dialog) opens the picker, which mounts two `input[type=file]` with `accept="image/jpg,image/jpeg,image/png,image/gif"`; `setInputFiles` on the first one uploads and closes the picker on its own — no `Select` click needed. The published cover is a CSS background, not an `<img>`, so an image probe on the permalink finds nothing and proves nothing: screenshot the top of the page instead.

The dialog scrolls as the body grows and pushes `Add Cover Image` above the viewport into a negative `y`. Attach after the body and the button is gone; set every scrollable container's `scrollTop` to 0 first, then re-read the rect. The two scroll containers here are the dialog shell and the editor pane, and zeroing both is what brings the header back.

Tags do not exist in this flow. The dialog has `Who can see it?`, the cover, the title, the body, a `Featured Post` checkbox, `Save to Studio` and `Submit`, and `Submit` publishes straight to `deviantart.com/<user>/journal/<Title-Slug>-<id>` with no settings step in between. A post file's `hashtags` therefore go out unapplied — record that as `degraded` rather than hunting for a control that is not there. (Tags reach a journal only by typing `#tag` into the body, which the `da-hashtag` mark picks up; that puts them in the text rather than in a tag field, so it is the user's call, not the run's.)

Blockquote is the wrong container for a command, and the numbers say why. Measured in the live editor: a plain paragraph renders at 18px in the regular face; a `blockquote` renders at 30px in `devioussans02extrabold`. Wrapping a command block in one therefore publishes it 1.67x larger than the body and bold — a pull-quote, not code. Checked again for anything better and there is nothing: the schema carries no `codeBlock` node and no `code` mark, `textStyle` has an empty attribute set so no font family can be applied to it, and the toolbar offers only `Bold`, `Italic`, `Alignment`, `Titles`, `Increase Indent`, `Decrease Indent`, `Blockquote` and `Horizontal Rule` (`applyIndentation` exists as a command but moved nothing).

So: **one plain `<p>` per command line**, at body size and body weight, with runs of two or more spaces converted to non-breaking spaces so the alignment survives. No frame, but the command reads as a command. Keep `blockquote` for an actual pull quote, which is what DeviantArt styles it for.
