# hackernoon

Editor 3.0 is what `hackernoon.com/new` opens now, and it is a different page from the Quill notes below. The `Start Draft` tile for `Blank Draft With Editor 3.0` (the second tile; the first, `Chowa`, is the collaborative editor) lands on `app.hackernoon.com/mobile/<id>` — that path is the editor for every viewport, and `/articles/<id>` redirects back to it. Its fields: `textarea.draft-title`, a `.ProseMirror` body that takes an HTML paste (headings, `pre`, anchors all survive), `textarea.excerpt`, a TL;DR textarea, `input.react-autosuggest__input` for tags, the `Category` chips and the `Is this story original on HackerNoon? Yes / No` pair, all in the `STORY SETTINGS` sidebar (gear, top right) that sits at `x≈2000` on a 1912-px viewport and is driven with `el.click()` from `page.evaluate`. Tags commit only through a suggestion click (`.react-autosuggest__suggestion`, dispatched `mousedown`/`mouseup`/`click`); `Enter` concatenates the typed text with the next tag. `Submit Story` opens a `Confirm? Yes / No` dialog; after `Yes` the header badge reads `Republished` (or `Published` for an original) and the story leaves `/drafts`.

The featured image belongs in `STORY SETTINGS`, not in the body. The sidebar's `CLICK TO UPLOAD FEATURED IMAGE` zone (`.main-image`, `Browse File`) is what the story card and the header show; an image pasted or uploaded into the body is an in-body figure, which is not the same thing and reads as one to the editors. The route that works, verified with a reload: the zone is not a drop target (its `dragover` never calls `preventDefault`, so a Playwright drop is refused) and a coordinate click on it opens no chooser; `document.querySelector('.main-image').click()` from `page.evaluate` is what opens its widget (`.uppload-container`: `Choose file` / `Direct URL` / stock tabs). Only once that modal is open does `setInputFiles` on `.uppload-container input[type=file]` register — the same call on the closed widget fires nothing, which is why an earlier run concluded the input was dead — and the modal then shows the preview with `Cancel / Upload`; click `Upload`, wait for `Saving draft...` to clear, and assert `.main-image img[src^="https://cdn.hackernoon.com/"]` before moving on. Two more things to know: the page holds two `.settings-screen` panels and the story one is the second, parked off-canvas by `transform: translateX(550px)` at every viewport width (the first `STORY SETTINGS` click toggles a class, not the transform), so read its elements by selector rather than by position; and a copy of the picture already sitting in the body as block 0 is deleted by putting the caret after its `span[contenteditable=false]` wrapper and pressing `Backspace`, then removing the empty paragraph it leaves. `Import from Direct URL` submits the page's form and reloads it; do not use it. A story submitted without its featured image is `degraded`.

`Is this story original on HackerNoon?` asks whether this text was published anywhere else first. `Yes` claims a HackerNoon exclusive; `No` marks it as republished and opens `Please enter the URL where the story was first published`, which takes the canonical URL of the earlier copy — the campaign's `devto` permalink, when that went out the same day. A campaign that publishes the same piece on several platforms answers `No` and names the first one; answering `Yes` misrepresents the piece to their editors. The answer resets when the page reloads, so set it last, right before `Submit Story`.

Check: `app.hackernoon.com` — the reader shell greets the user by handle, which confirms the session. Compose: in theory new draft → title, markdown body → submit for review, and submission is the terminal state for this skill (ledger `pending-approval`).

The editor is reachable: `app.hackernoon.com/new` redirects to `hackernoon.com/new`, whose Start Draft button opens `app.hackernoon.com/articles/<id>` with the full editor — `textarea.draft-title`, a `.ql-editor` body, `input.react-autosuggest__input` for tags, `textarea.excerpt` and `textarea.tldr` in the right sidebar. (An earlier run reported this button dead; a plain coordinate click on it works.)

Submission is gated by four checks that surface one at a time, each as a `Before submitting, …` line replacing the last, so the flow looks stuck unless you re-read that line after every attempt. In order: a story description (`textarea.excerpt`), at least one tag, the "Is this story original on HackerNoon?" Yes/No answer, and a Category (Web3 / AI and ML / Cybersecurity / Software Engineering / Business / Other). Only when that line is gone will `Submit Story` do anything.

The sidebar holding the last two gates is unreachable by mouse at any window size. Those controls sit at `x≈2624` and move further right as the viewport widens, because the layout scales with the window. This is the legitimate case for `el.click()` from `page.evaluate` — it cleared both. The excerpt is likewise off-viewport: set it with the native value setter plus an `input` event rather than by clicking.

The originality answer is a claim about the user's content, not a UI step. Answer it from what the run actually knows — a text written for this platform and not published elsewhere is `Yes`; a cross-post is `No` and wants the canonical URL. When the campaign published sibling articles on other platforms the same day, say which answer was given in the report so the user can correct it.

Read-back: the story leaves `app.hackernoon.com/drafts` on submission, which is the available evidence — HackerNoon renders no queue badge that can be read back, so record `pending-approval` and say the queue state itself is unverified.

The excerpt has a 160-character cap, and the editor states the overshoot rather than the limit: a 269-character description produced `269 of 160` beside the field and blocked submission. Measure the excerpt against 160 during the source scan rather than at the composer, and cut it at a sentence boundary in the author's own wording.

A native-setter write into `textarea.excerpt` does not survive a reload. Setting the value through the prototype setter plus an `input` event satisfies the gate on screen, and the field comes back empty after the page reloads, because this editor persists what reached it as keystrokes. Even where the field is off-viewport, focus it in-page and `insertText`, then blur it and confirm the value after one reload before treating that gate as cleared.

`SUBMIT STORY` can sit outside the viewport at every width, and that is the end of the road. It measured `x=2057` on a 1912-px viewport, and a resize to 2600 px of height moved nothing horizontally — the layout scales with the window, so the button travels right as fast as the viewport grows. `el.click()` on it does raise the `Confirm?` dialog, but `Yes` there did not commit the story on three attempts: the draft stayed in `/drafts` and the header badge never changed. Record `failed` with the `app.hackernoon.com/mobile/<id>` draft URL, say the draft is complete and one click from submission, and stop — the user finishes it in their own window.
