# blogger

Check: `blogger.com` signed in redirects to `/blog/posts/<blogId>`, with the blog selector (`listbox "Blog Selection"`) and the `New Post` button in the drawer; signed out lands on the Google sign-in page. The blog's public address is in the page as `<name>.blogspot.com` and is the read-back base.

Compose: `New Post` opens `/blog/post/edit/<blogId>/<postId>` and creates the draft immediately (the page says `Creating new post...`), so an abandoned editor is a draft in the Posts list under the `Draft` filter: finish or delete it before retrying, or the blog ends with two of the same article. `textbox "Title"` is the title. The body is the Compose view, a contenteditable inside an iframe, with the `Toggle view` listbox switching to `HTML view`. Typed markdown stays literal in Compose view, so a formatted article goes in through HTML view as HTML, headings and links included; the toolbar's `Insert or Edit Link`, `Insert image` and `Insert video` controls cover the Compose route when needed. The image goes in through `Insert image` at the top of the body.

Post settings sidebar: `Labels` (comma-separated, with suggestions from the blog's existing labels), `Published on` (a future date schedules), `Permalink` (custom slug), `Location`, `Options`. `Publish` is the top-right button; `Preview` beside it opens a new tab. The labels come from the post's `hashtags` list, mapped to existing labels where they match.

Read-back: `<name>.blogspot.com`, newest post at `/<yyyy>/<mm>/<slug>.html`; confirm the title, the headings rendered as headings and the image.

Three defects from one run, all in the finished post and none visible while composing:

**A leading space before the first word.** The published article opened on ` Run DeepSeek…` — one space the source does not have. HTML view preserves whatever whitespace the pasted markup carries, so a document whose first element is `\n<p>…` or that is set through a helper adding a newline publishes with the indent. Trim the HTML to start exactly at `<` before switching views, and read the first 20 characters of the published body back against the source's first 20.

**Labels are the hashtags, and the run must actually fill them.** They live in the Post settings sidebar on the right of the editor, as a comma-separated `Labels` field with suggestions from the blog's existing labels. This is the only place tags exist on Blogger — a `#tag` line in the body indexes nothing. Open the `Labels` row, type the frontmatter `hashtags` as one comma-separated string, close the row and confirm the chips render before publishing. A run that reported "the sidebar Labels field did not expose an input my probe could reach" had not opened the row: the input mounts when the row is expanded, not before.

**The image goes in first, at the very top, through the editor's own control.** `Insert image` -> `Upload from computer` opens the file chooser; the picture lands at the caret, so put the caret at the very start of the body before opening it. Then set the size: click the inserted image and pick from the size row that appears under it (`Small` / `Medium` / `Large` / `X-Large` / `Original size`). `X-Large` is usually right, but check it against the body — an image wider than the text column looks broken, so step down one size if the rendered width exceeds the paragraph width. Verify on the published page by geometry: the `img`'s `y` smaller than the first paragraph's, and its rendered width no greater than the body column's.
