# Навыки для контента: от источника до опубликованных постов

Пошаговое руководство по пяти навыкам `awesome-content-*`, написанное для того, кто никогда не пользовался AI-агентом для кода. Начинается с «откройте терминал» и заканчивается постами, опубликованными в ваших аккаунтах.

Если вы уже каждый день работаете в Claude Code или Codex — переходите сразу к [части 3](#часть-3--подключение-браузера): только она специфична для этих навыков.

English version: [content-skills-guide.md](content-skills-guide.md).

## Что именно вы настраиваете

Дальше по тексту встречаются четыре слова, и ни одно не значит того, что кажется с первого раза.

- **Агент** — программа, с которой вы разговариваете в окне терминала. Вы пишете запрос обычными словами; она читает файлы, запускает команды и правит что-то на вашей машине. Claude Code и OpenAI Codex — это агенты. В этом руководстве все конкретные команды даны для Claude Code.
- **Навык** — папка с написанными инструкциями, которую агент подгружает, когда ваш запрос под неё подходит. Навык не добавляет никакого софта: это документ, объясняющий агенту, как правильно сделать одну работу. Шесть навыков в этом репозитории отвечают за написание постов, их картинки и публикацию.
- **MCP-сервер** — маленькая вспомогательная программа, которую агент запускает в фоне, чтобы дотянуться до чего-то вне себя. Здесь — до вашего браузера.
- **Мост** — MCP-сервер плюс браузерное расширение вместе. Он позволяет агенту действовать внутри того окна браузера, которым вы и так пользуетесь, в сессиях, где вы уже залогинены. Ваши пароли через него не проходят, потому что ни один пароль нигде не вводится.

Схема целиком: вы говорите агенту → агент читает навык → навык велит ему управлять вашим браузером через мост → посты появляются в ваших аккаунтах.

Две вещи нужны до всего остального: аккаунт у AI-провайдера, по которому агент тарифицируется (Claude Code требует подписку Claude или оплату по API — заведите это у провайдера заранее, без этого агент не запустится), и аккаунты на площадках, куда вы собираетесь публиковать, уже залогиненные.

## Шесть навыков

| Навык | Что на входе | Что на выходе |
| --- | --- | --- |
| [awesome-content-voice](../skills/awesome-content-voice) | Ваши прошлые посты, файлы или интервью | Один переиспользуемый профиль авторского голоса |
| [awesome-content-campaign](../skills/awesome-content-campaign) | Репозиторий, сайт, файлы — продукт, о котором нужно рассказать, плюс тема, дата старта и длительность | Папки по датам публикации с файлами постов, по одному на слот площадки, плюс манифест |
| [awesome-content-repurpose](../skills/awesome-content-repurpose) | Один готовый текст: ссылка, файл, вставленные заметки | Три файла поста — short, regular и long, — каждый со списком своих площадок, без расписания |
| [awesome-content-graphics](../skills/awesome-content-graphics) | Референс: текст, изображения, ссылка — то, о чём должна быть картинка | Набор нарисованных картинок того размера, который вы назвали, и выбранная вами |
| [awesome-content-image-adapter](../skills/awesome-content-image-adapter) | Одна готовая картинка и посты, к которым она относится | Та же картинка в двух кадрах, горизонтальном 16:9 и вертикальном 9:16; каждая площадка берёт тот, что совпадает с её кадром |
| [awesome-content-publisher](../skills/awesome-content-publisher) | Папка файлов постов | Опубликованные посты в ваших аккаунтах плюс журнал публикаций |

`campaign` и `repurpose` пишут в одном формате, который читает `publisher`. Берите `campaign`, когда есть источники о продукте и нужно расписание; берите `repurpose`, когда есть одна статья и она нужна везде. В обоих случаях материал превращается в три файла: лонгрид, обычный пост на его основе и короткий пост, и каждый без изменений уходит на все площадки своей группы.

`voice` и `graphics` — необязательные входы для остальных трёх: профиль голоса задаёт, как посты звучат, графика даёт им картинку. `image-adapter` — шаг после картинки: он раскладывает её в горизонтальный и вертикальный кадр и точно так же работает отдельно с любым готовым изображением.

## Часть 1 — Установка агента

### Шаг 1.1 — Откройте терминал

Все команды ниже набираются в окне терминала.

| Система | Как открыть |
| --- | --- |
| Windows | Пуск → наберите `PowerShell` → откройте **Windows PowerShell** |
| macOS | ⌘+Пробел → наберите `Terminal` → Enter |
| Linux | Ctrl+Alt+T или **Терминал** в меню приложений |

Набираете одну команду, нажимаете Enter и ждёте, пока вернётся приглашение, прежде чем набирать следующую.

### Шаг 1.2 — Установите Node.js и Git

Две программы, обе бесплатные, обе ставятся один раз.

**Node.js** запускает и самого агента, и установщик навыков, и браузерный мост. Скачайте сборку **LTS** с [nodejs.org](https://nodejs.org) и поставьте с настройками по умолчанию.

**Git** скачивает этот репозиторий в части 2. Возьмите его на [git-scm.com](https://git-scm.com/downloads) — там есть версии для Windows, macOS и Linux. На macOS первая же команда `git` может вместо этого предложить поставить инструменты разработчика Apple; согласиться достаточно.

Затем закройте терминал, откройте заново и проверьте обе:

```bash
node --version
git --version
```

Два номера версий, например `v24.15.0` и `git version 2.54.0`, означают, что всё получилось. `command not found` или «не является внутренней или внешней командой» — значит терминал был открыт до конца установки: закройте и откройте его снова.

### Шаг 1.3 — Установите Claude Code

```bash
npm install -g @anthropic-ai/claude-code
```

Затем проверьте:

```bash
claude --version
```

Другие способы установки (нативный установщик, Homebrew) описаны в [документации Claude Code](https://code.claude.com/docs). Взять вместо него другой агент — Codex, Gemini CLI, Cursor — тоже нормально: у каждого шага дальше есть там аналог, а пути установки перечислены в [таблице в README](../README.md#install). Конкретные команды в этом руководстве — от Claude Code.

### Шаг 1.4 — Запустите и войдите в аккаунт

Создайте рабочую папку и запустите агента внутри неё:

```bash
mkdir my-posts
cd my-posts
claude
```

При первом запуске откроется окно браузера для входа в аккаунт Claude. После этого появится приглашение, куда вы пишете обычными словами.

Две вещи, которые стоит запомнить сразу: **Esc** прерывает то, что агент делает прямо сейчас, а `/exit` (или Ctrl+C дважды) закрывает его. Ничего из описанного в этом руководстве не произойдёт без вашего подтверждения.

### Шаг 1.5 — Выберите модель

Поведение агента задают две настройки: какая модель и сколько усилий она тратит на шаг. Указывайте обе при запуске:

```bash
claude --model opus --effort medium
```

Внутри запущенной сессии то же самое меняется командой `/model`.

**Рекомендуется: Opus 5 на уровне усилий `medium`.** Этого хватает на весь конвейер в обычном случае — написать посты, заполнить композеры, которые совпадают со своими заметками, прогнать сверку с файлом-источником по каждой площадке. Именно на этой настройке замерены пять минут на площадку из раздела ниже.

**Переключайтесь на `high`, когда проход длинный или площадки незнакомые.** Разница не в качестве текста, а в том, что происходит, когда страница ведёт себя не так, как ожидалось. На `high` агент терпеливее разбирается, *почему* отправка молча не сработала, охотнее идёт по лестнице способов клика вместо того, чтобы повторять один и тот же неудачный, и аккуратнее выбирает способ починки, который не потеряет наполовину заполненный черновик. Он же лучше справляется с решениями в пишущих навыках — какой абзац выбросить, когда пост не влезает в лимит площадки, какие утверждения имеет право нести картинка. Плата за это — время: каждый шаг идёт дольше.

Практическое разделение: письмо и графика — `medium`, публикация по многим площадкам — `high`. `low` здесь брать не стоит: эти навыки — длинные многошаговые процедуры с подтверждениями, а дешёвые шаги как раз то место, где подтверждение проскакивают. `xhigh` и `max` рассчитаны на рассуждения тяжелее, чем нужно этой работе.

Это рекомендация из того, как ведут себя навыки, а не результат замера.

## Часть 2 — Установка навыков

Выйдите из агента (`/exit`) и выполните в том же терминале:

```bash
git clone https://github.com/khasky/awesome-agent-skills.git
cd awesome-agent-skills
npx skills add ./skills -g -s "*" -a claude-code -y
```

Первая команда скачивает репозиторий, третья ставит все навыки в Claude Code. В первый раз она попросит скачать вспомогательный пакет `skills` — согласитесь.

Проверьте, что они на месте. Установщик пишет в одно из двух мест в зависимости от машины, так что смотрите оба:

| Оболочка | Команда |
| --- | --- |
| PowerShell | `Get-ChildItem ~\.claude\skills, ~\.agents\skills` |
| macOS, Linux | `ls ~/.claude/skills ~/.agents/skills` |

Папки `awesome-content-campaign`, `awesome-content-publisher` и остальные **в любом** из двух списков означают, что всё получилось — Claude Code читает оба. Если пусты оба, в [разделе Install в README](../README.md#install) описан ручной путь и разница между копиями и симлинками.

Альтернатива для Claude Code, если клонировать не хочется: внутри агента наберите `/plugin marketplace add khasky/awesome-agent-skills`, затем `/plugin install awesome-agent-skills@awesome-agent-skills`.

## Часть 3 — Подключение браузера

Это та часть, которая нужна именно для публикации. Делается один раз на профиль браузера.

**Какой браузер:** тот, где вы уже залогинены в Instagram, LinkedIn, Mastodon и остальных. В этом весь смысл моста — агент постит от вашего имени, в ваших существующих сессиях, и при этом никогда не вводит пароль, не проходит 2FA и не кликает капчу. Если аккаунты разбросаны по двум браузерам, выберите тот, где их больше, и дологиньтесь в остальные там руками.

Chrome, Edge или другая сборка Chromium. Firefox и Safari в этом режиме не поддерживаются.

### Шаг 3.1 — Установите расширение

Откройте [страницу расширения Playwright](https://chromewebstore.google.com/detail/playwright-extension/mmlmfjhmonkocbjadbfplnigmagldckm) в том браузере, которым нужно управлять, и установите его. Edge ставит его из того же листинга Chrome Web Store. Исходники и заметки: [microsoft/playwright, packages/extension](https://github.com/microsoft/playwright/tree/main/packages/extension).

### Шаг 3.2 — Возьмите токен профиля

В том же браузере откройте адрес:

```text
extension://mmlmfjhmonkocbjadbfplnigmagldckm/status.html
```

Страница показывает токен подключения и кнопку перегенерации. Скопируйте токен. Он разрешает локальной программе подключиться к этому профилю браузера; это не пароль и не ваш аккаунт.

Токен именно на профиль: у второго браузера или второго профиля в том же браузере будет свой.

### Шаг 3.3 — Зарегистрируйте мост у агента

**Одного моста достаточно.** Публикация идёт ровно через один браузер — тот, о котором сказано в начале этой части. Вторую запись добавляйте только если держите отдельные браузеры под эти аккаунты и хотите выбирать между ними в начале прогона: публикатор тогда сам спросит, какой использовать, до первого действия.

В терминале, одной строкой, подставив свой токен вместо `<token>`:

```bash
claude mcp add playwright -s user -e PLAYWRIGHT_MCP_EXTENSION_TOKEN=<token> -- npx -y @playwright/mcp@latest --extension --browser chrome
```

Для Edge меняются имя и браузер:

```bash
claude mcp add playwright-edge -s user -e PLAYWRIGHT_MCP_EXTENSION_TOKEN=<token> -- npx -y @playwright/mcp@latest --extension --browser msedge
```

`playwright` и `playwright-edge` — имена, которые выбираете вы: именно их агент покажет, когда будет спрашивать, какой мост использовать, так что называйте по браузеру. `-s user` делает мост доступным в любой папке, а не только в текущей.

Убедитесь, что запись появилась:

```bash
claude mcp list
```

`--browser` принимает имя браузера или канал Chrome:

| Значение | Что открывает |
| --- | --- |
| `chrome` | Google Chrome, стабильная версия |
| `msedge` | Microsoft Edge, стабильная версия |
| `chrome-beta` · `chrome-dev` · `chrome-canary` | соответствующий канал Chrome |
| `msedge-beta` · `msedge-dev` · `msedge-canary` | соответствующий канал Edge |
| `chromium` | обычная сборка Chromium |

`firefox` и `webkit` — допустимые значения `--browser` для Playwright вообще и **не** для этого режима: в собственной справке сервера сказано, что `--extension` подключается к запущенному браузеру, только Edge или Chrome. С такой настройкой прогон просто не подключится.

Остальные форки Chromium — Brave, Vivaldi, Opera, Arc — расширение из того же листинга принимают, но у `--browser` нет значения, которое их называет, а режим расширения документирован как Chrome и Edge. Считайте их неподдерживаемыми для публикации, а не поводом для отладки.

Ещё один флаг, полезный когда в браузере несколько профилей: допишите в конец `--profile-dir-name "Profile 1"`, чтобы выбрать каталог профиля. Без него сервер берёт последний использованный профиль, где установлено расширение — обычно это правильный выбор, но его стоит закрепить явно, если аккаунты живут в профиле, которым вы не пользуетесь каждый день.

<details>
<summary>Если вместо команды нужно править файл конфигурации</summary>

У некоторых агентов нет команды `mcp add`, и запись нужно вписать в JSON-файл. Форма та же:

```jsonc
"playwright":      { "command": "npx",
                     "args": ["-y", "@playwright/mcp@latest", "--extension", "--browser", "chrome"],
                     "env": { "PLAYWRIGHT_MCP_EXTENSION_TOKEN": "<токен этого профиля>" } },
"playwright-edge": { "command": "npx",
                     "args": ["-y", "@playwright/mcp@latest", "--extension", "--browser", "msedge"],
                     "env": { "PLAYWRIGHT_MCP_EXTENSION_TOKEN": "<токен этого профиля>" } }
```

Какой это файл и где он лежит — вопрос к документации вашего агента. Для Claude Code команда выше пишет его за вас, поэтому она и рекомендуется.

</details>

**Почему `--browser` важен.** Без него сервер открывает свою служебную страницу в браузере по умолчанию. Если обе записи уходят в браузер по умолчанию, та, чей токен принадлежит другому браузеру, будет ждать вечно: стартует чисто, слушает порт, отвечает на `initialize` и не отвечает ни на один вызов инструмента. У этого симптома ровно одна причина, и она здесь.

### Шаг 3.4 — Перезапустите агента

Закройте его (`/exit`) и запустите `claude` снова, чтобы он подхватил новую конфигурацию. Токен, прописанный без перезапуска, выглядит точно так же, как токен, который не сработал.

### Шаг 3.5 — Проверьте, что мост живой

Убедитесь, что браузер из шага 3.1 **открыт**, и напишите агенту:

```text
Покажи список открытых вкладок браузера
```

- Одна `connect.html` — норма. Это собственная страница моста, просто других вкладок нет. Не трогайте эту вкладку.
- Перечислены ваши настоящие вкладки — тоже норма.
- Одна `about:blank` — отказ: агент попал в чистый пустой браузер без ваших сессий.
- «MCP-серверу нужна аутентификация» — токен не подхвачен. См. [Если что-то пошло не так](#если-что-то-пошло-не-так).

## Часть 4 — Первый прогон, который ничего не публикует

Сделайте это до всего настоящего. Прогон проходит все проверки и не публикует ничего.

Нужна папка хотя бы с одним файлом поста. Либо пусть его напишет навык:

```text
Используй awesome-content-repurpose на https://example.com/some-article — только mastodon и bluesky
```

либо напишите руками, как [ниже](#как-написать-файл-поста-руками).

Затем:

```text
Используй awesome-content-publisher на ./my-campaign-folder --dry-run
```

`--dry-run` выполняет проверку моста, скан файлов, проверку логина по каждой площадке и печатает полный план — и на этом останавливается. Прочитайте план. Это тот же план, который вы будете утверждать по-настоящему, так что именно здесь бесплатно находятся не та площадка, отсутствующая картинка или файл, который не прошёл скан.

## Часть 5 — Публикация по-настоящему

Каждый навык срабатывает на обычную формулировку. Явное имя делает выбор однозначным. В Claude Code можно также набрать `/awesome-content-publisher`, и навык подгрузится напрямую.

### Профиль голоса

```text
Используй awesome-content-voice: собери профиль моего голоса из https://myblog.example и постов в ./writing/
```

На выходе один файл профиля. Пишется один раз, переиспользуется всеми последующими запусками.

### Посты из источников о продукте

```text
Используй awesome-content-campaign на этом репозитории и https://myproduct.example — две недели, площадки, где у меня реально есть аккаунты
```

Вас спросят про площадки, период и язык.

### Посты из одной готовой статьи

```text
Используй awesome-content-repurpose на https://example.com/my-article — все три формы
```

Тот же формат, без расписания. Это тот вариант, который нужен, когда источник — один текст.

### Картинка

```text
Используй awesome-content-graphics для этой кампании: вертикаль 1080x1350, 100 картинок
```

Вы даёте референс — статью, несколько картинок, ссылку или всё сразу. Прогон одной фразой говорит, о чём, по его мнению, должна быть картинка, чтобы вы поправили это до того, как будет сделано сто картинок не о том. Дальше спрашивает количество: 10, 20, 50 или 100.

Набор рисует сам агент — никакого сервиса регистрировать не нужно, ключей задавать не надо, ставить нечего. Он сочиняет каждую картинку, складывает всё в одну папку и открывает её. Вы отвечаете номером. Если не подошло ничего — просите ещё круг: набор будет собран из других идей, а не перекрашен из тех же. Предыдущие круги остаются на диске.

Выбранная картинка копируется в отдельную папку, которая открывается сама по себе — чтобы потом не искать нужный файл среди девяноста девяти проигравших.

Что этим путём получается: плоская графика — форма, шрифт, цвет, схемы, узоры. Фотографий он не даёт. Нужна фотография — дайте свою и сразу переходите к подгонке под платформы.

### Подгонка картинки под каждую платформу

```text
Используй awesome-content-image-adapter для ./poster.png
```

Каждая площадка показывает картинку в своём кадре: широком на сайте статей, вытянутом в ленте телефона, квадратном в профиле. Навык берёт одну утверждённую картинку и выдаёт два файла: `horizontal.png` 16:9 для широких кадров и `vertical.png` 9:16 для квадратных, портретных и вертикальных, где вся картинка остаётся резкой посередине, так что квадратная обрезка или 4:5 всё равно показывает её целиком. Отдельным запуском он кладёт их во временную папку и открывает её. В составе цепочки — рядом с постами, каждый пост указывает картинки для своих площадок, и публикатор даёт каждой площадке подходящую.

Ничего не перерисовывается. Кадр шире вашей картинки — это минимальная обрезка по центру; кадр выше — картинка сохраняется целиком, а место сверху и снизу заполняется размытым затемнённым продолжением того же изображения.

### Публикация

```text
Используй awesome-content-publisher на ./my-campaign-folder
```

До первой публикации вы получите: проверку моста, скан источника с жёсткой остановкой на любом дефектном файле, проверку логина по каждой площадке и план прогона, который нужно утвердить.

Пока идёт прогон, браузер занят — агент кликает внутри него. Не трогайте его и рассчитывайте примерно на пять минут на площадку. **Esc** останавливает прогон; благодаря журналу публикаций повторный запуск продолжит с места остановки, а не опубликует что-то дважды.

## Запуск цепочкой

Обычный порядок и что передаётся на каждом шаге:

1. **`awesome-content-voice`** — один раз навсегда. Сохраните файл профиля.
2. **`awesome-content-campaign`** или **`awesome-content-repurpose`** — укажите источник и профиль голоса. Прочитайте черновики. Это момент, когда правят формулировки: все последующие стадии считают эти файлы авторским текстом и не переписывают его.
3. **`awesome-content-graphics`** — читает материал кампании, спрашивает количество картинок и отдаёт набор. Выберите одну по номеру или попросите ещё круг. Своя готовая картинка вместо этого — тот же шаг, просто другой ответ.
4. **`awesome-content-image-adapter`** — запускается сразу после выбора, без отдельного вопроса, и раскладывает картинку в горизонтальный и вертикальный кадр рядом с постами.
5. Руками делать нечего: файлы постов ссылаются на картинку, которая лежит рядом с ними.
6. **`awesome-content-publisher`** — укажите папку. Утвердите план прогона. Дайте отработать.

Одна фраза на всю цепочку тоже работает — агент остановится на каждом гейте, где нужен ваш ответ:

```text
Прогони https://example.com/my-article через awesome-content-repurpose, сделай для него графику, потом опубликуй всё через awesome-content-publisher
```

## О чём вас спросят

Подтверждения существуют потому, что действия публичные, а часть из них необратима. Ожидайте:

- **Какой браузерный мост**, если настроено больше одного.
- **Какие площадки** и что делать с теми, для которых нет файла поста.
- **Просроченные посты**: публиковать сейчас по порядку, пропустить или сдвинуть расписание.
- **Количество хештегов**, если оно расходится с нормой площадки — один общий вопрос с названием площадки, текущим числом, целевым и точным списком добавляемых или снимаемых тегов.
- **План прогона** таблицей, до первого поста.
- **Всё необратимое**: рассылка на Substack, платная аудитория, пост в группу с чужой модерацией.
- **Сабреддит для reddit**, если reddit в наборе — навык не выберет его за вас.

Отвечайте обычными словами или выбирайте из предложенных вариантов. Ничего не публикуется, пока вопрос без ответа.

## Что появляется на диске

Ничего не прячется, и ничего не уходит с вашей машины, кроме самих постов.

```text
my-campaign-folder/
├── 2026-09-01_10-00_Europe-Kyiv_post-title_mastodon.md   по файлу на пост
├── mastodon.png                                           та же картинка в кадре этой площадки
├── campaign.md                                            манифест, если писала кампания
├── image.png                                              общая картинка постов
└── publish-state/
    └── ledger.json                                        что опубликовано, куда и когда
```

Журнал публикаций (`ledger.json`) — самое важное: благодаря ему остановленный прогон продолжается, а не публикует повторно, и в нём лежат URL каждого поста и доказательства, собранные аудитом. Храните его вместе с кампанией.

Графика складывается в отдельную папку, абсолютный путь к которой прогон печатает: рендеры, HTML, из которого они собраны, контактный лист и страница-галерея.

## Как написать файл поста руками

Навык для этого не нужен. Файл поста — это Markdown с блоком метаданных (frontmatter) сверху, а расписание зашито в имя:

```text
YYYY-mm-dd_HH-mm_<таймзона>_<заголовок-поста>_<площадка>.md
```

Ровно пять полей через `_`, а внутри поля допустим только `-`: символ `_` внутри поля ломает разбор. Таймзона — это имя IANA, где `/` и `_` заменены на `-`: `Europe/Kyiv` → `Europe-Kyiv`.

`2026-09-01_10-00_Europe-Kyiv_a-million-tokens_mastodon.md`:

```markdown
---
platform: mastodon
scheduled: 2026-09-01 10:00
timezone: Europe/Kyiv
title: "A million tokens, drawn to scale"
attachments:
  - file: image.png
    alt: "Карточка, сравнивающая миллион токенов с 3000 печатных страниц"
links: ["https://example.com"]
hashtags: []
status: draft
---

Тело поста ровно в том виде, в каком его нужно опубликовать.
```

`target` — дополнительная строка метаданных для площадок, которым нужна цель: сабреддит, инстанс, доска, группа. Публикатор отказывается угадывать её.

Файл, который пишет `awesome-content-repurpose` или `awesome-content-campaign`, вместо одной строки `platform` несёт список `platforms` и публикуется на каждую площадку из него. Публикатор добавляет под каждую площадку то, что помещается целиком: заголовок в собственное поле заголовка, если оно есть, хештеги из списка `hashtags` и, у короткого поста, одну ссылку. Файл, написанный вручную с одной строкой `platform`, работает ровно так, как показано выше.

Названия площадок — это те же слаги, которыми пользуются навыки: `mastodon`, `bluesky`, `linkedin`, `instagram`, `pixelfed`, `medium`, `teletype` и так далее. Полная таблица — в [справочнике площадок навыка `awesome-content-campaign`](../skills/awesome-content-campaign/references/platforms.md).

## Сколько это занимает

Замерено на реальном проходе по 25 площадкам, по меткам времени из журнала самого публикатора. Цифра — это полный цикл на площадку: открыть композер, заполнить, приложить картинку, отправить, прочитать пермалинк, сверить с файлом-источником, записать журнал.

| Тип композера | Площадки | На пост |
| --- | --- | --- |
| Простое текстовое поле | x, bluesky, threads, mastodon, truthsocial, minds, peerlist, lemmy, quora, bastyon | 2–6 мин |
| Поле с Markdown | devto, wonderful-dev | 2–4 мин |
| Подпись с обязательной картинкой | instagram, pixelfed, pinterest | 4–8 мин |
| Визуальный редактор, короткий пост | tumblr, daily-dev, patreon, ko-fi, buymeacoffee | 3–9 мин |
| Визуальный редактор, длинная статья | medium, hashnode, substack, hackernoon, teletype | 4–9 мин |

Цифры по проходу целиком из того же журнала:

- **15 площадок за 73 минуты** непрерывной работы — около 5 минут на каждую, на эту цифру и стоит планировать.
- **Первая площадка сессии стоит дороже**: на неё приходятся гейт моста, проверки логинов и скан источника. Закладывайте 15–20 минут до выхода первого поста.
- **Графика считается отдельно**: набор из 100 рендеров с геометрическим гейтом и отсевом дублей — это самостоятельная задача, а не часть того часа.
- **Между разными площадками пауз нет.** Два поста на *одну и ту же* площадку разносятся минимум на 2 часа; разные площадки идут подряд.

Что удлиняет проход: композер, чья живая страница изменилась с момента написания заметок; площадка, потребовавшая ремонтного прохода после сверки с источником; и любой гейт, ждущий вашего ответа.

## Если что-то пошло не так

**`claude` не распознаётся после установки.** Закройте терминал и откройте новый. Установщики прописывают путь только для новых окон.

**Агент не реагирует на имя навыка.** Навык поставлен после запуска агента — перезапустите его. Если не помогло, проверьте список папок из [части 2](#часть-2--установка-навыков).

**Агент говорит, что браузерным инструментам нужна аутентификация.** Мост настроен и не подключён. Откройте страницу из шага 3.2 в нужном браузере: `No clients are currently connected` подтверждает, что запущенный сервер спарен с другим браузером. Сначала проверьте `--browser`.

**Сервер стартует, отвечает и никогда не завершает вызов инструмента.** Та же причина. Его служебная страница открылась в браузере по умолчанию, где лежит другой токен.

**В списке вкладок только `about:blank`.** Вы на чистом запущенном браузере без ваших сессий. Расширение не подключено.

**В списке вкладок только `connect.html`.** Это норма — собственная служебная страница моста. Не трогайте эту вкладку, прогон откроет свою.

**Токен поменялся.** На странице статуса расширения из шага 3.2 есть кнопка перегенерации. После неё конфигурация со старым токеном протухшая, пока вы её не обновите — `claude mcp remove playwright`, затем добавить заново — и не перезапустите агента.

**Площадка посреди прогона просит логин или показывает капчу.** Прогон на этом останавливается и отдаёт браузер вам. Залогиньтесь сами в том окне и скажите агенту продолжать. Эту часть он за вас не сделает никогда.

**Навык графики уходит искать сервис генерации.** Не должен: картинки рисует сам агент, подключать нечего. Прогон, который остановился в поисках генератора, прочитал навык неверно — скажите это и попросите нарисовать набор. Единственное, что ему нужно со стороны, — чем превратить нарисованное в PNG; без этого он всё равно отдаёт рисунки и говорит, что не сконвертировал их.

**Пост опубликовался с неправильным форматированием.** Публикатор сверяет каждый опубликованный пост с файлом-источником и чинит расхождения: правкой там, где площадка её позволяет; удалением и перепубликацией — только в пределах 5 минут и только при нулевой реакции; и прямым сообщением вам там, где площадка не позволяет ни того, ни другого. Если нашли пропущенное — скажите: он переоткроет весь аудит, а не залатает одну названную строку.

**Нужно всё остановить.** Esc. Журнал помнит, что уже опубликовано, поэтому следующий запуск продолжит, а не повторит.

## Чего публикатор не делает никогда

- Не вводит пароль, не проходит логин и не заполняет 2FA.
- Не решает и не обходит капчу или проверку на бота.
- Не обращается к API площадки — ни чтобы опубликовать, ни чтобы посчитать посты, ни чтобы выяснить, существует ли что-то. Всё делается так, как делает человек: глядя на страницу и кликая по ней.
- Не удаляет и не редактирует опубликованный пост, кроме как по вашей явной просьбе про конкретный пост.
- Не работает больше чем с одним аккаунтом на площадку и не ведёт аккаунты в масштабе, который площадка запрещает.

Темп публикации — часть того же договора: площадки лимитируют и помечают быстрые скриптовые очереди даже на легитимных аккаунтах, и правила интервалов держат работу внутри обычного профиля использования.
