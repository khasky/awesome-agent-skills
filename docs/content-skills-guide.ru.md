# Content-навыки: от источника до опубликованных постов

Пошаговое руководство по пяти навыкам `awesome-content-*`, написанное для того, кто ни разу их не запускал. Здесь: что делает каждый навык, что нужно установить до первого запуска, как настроить браузерный мост для публикатора, как запускать навыки по отдельности, как связывать их в цепочку и сколько времени занимает реальный проход.

## Пять навыков

| Навык | Что на входе | Что на выходе |
| --- | --- | --- |
| [awesome-content-voice](../skills/awesome-content-voice) | Ваши прошлые посты, файлы или интервью | Один переиспользуемый профиль авторского голоса |
| [awesome-content-campaign](../skills/awesome-content-campaign) | Репозиторий, сайт, файлы — продукт, о котором нужно рассказать | Папка датированных файлов постов, по одному на слот площадки, плюс манифест |
| [awesome-content-repurpose](../skills/awesome-content-repurpose) | Один готовый текст: ссылка, файл, вставленные заметки | Тот же формат папки, без расписания |
| [awesome-content-graphics](../skills/awesome-content-graphics) | Факты, на которые картинка имеет право ссылаться | Набор отрендеренных PNG, собранных локально из HTML и CSS |
| [awesome-content-publisher](../skills/awesome-content-publisher) | Папка файлов постов | Опубликованные посты в ваших аккаунтах плюс ledger |

`campaign` и `repurpose` пишут в одном формате, который читает `publisher`. Берите `campaign`, когда есть источники о продукте и нужно расписание; берите `repurpose`, когда есть одна статья и нужно разложить её по регистрам площадок.

`voice` и `graphics` — необязательные входы для остальных трёх: профиль голоса задаёт, как посты звучат, графика даёт им картинку.

## Что нужно заранее

### 1. Агент с поддержкой Agent Skills

Claude Code, Claude.ai, OpenAI Codex, Gemini CLI, Cursor, GitHub Copilot, opencode, Amp, Windsurf, Antigravity. Любой агент, читающий формат [Agent Skills](https://agentskills.io).

### 2. Установленные навыки

См. [Install](../README.md#install) в README. Коротко: скопировать или слинковать папки `skills/<имя>` в директорию навыков вашего агента.

### 3. Браузер с активными сессиями

Chrome, Edge или другая сборка Chromium. Войдите руками в каждую площадку, куда собираетесь публиковать. Публикатор никогда не вводит пароль, не проходит 2FA и не кликает капчу — он работает в тех сессиях, которые у вас уже есть.

Отдельный профиль браузера только под эти аккаунты — нормальная схема, мост её поддерживает: один токен на профиль.

### 4. Мост Playwright MCP extension

Это та часть, которую обычно пропускают. Публикатор не запускает свой браузер — он подключается к вашему, чтобы постили именно ваши залогиненные сессии. Подключение — это сервер Playwright MCP в режиме `--extension` в паре с браузерным расширением.

Firefox и Safari в этом режиме не поддерживаются.

## Настройка браузерного моста

Делается один раз на профиль браузера.

**Шаг 1 — установить расширение.** Откройте [страницу расширения Playwright](https://chromewebstore.google.com/detail/playwright-extension/mmlmfjhmonkocbjadbfplnigmagldckm) в том браузере, которым нужно управлять, и установите его. Edge ставит его из того же листинга Chrome Web Store. Исходники и заметки: [microsoft/playwright, packages/extension](https://github.com/microsoft/playwright/tree/main/packages/extension).

**Шаг 2 — взять токен профиля.** В том же браузере откройте:

```text
extension://mmlmfjhmonkocbjadbfplnigmagldckm/status.html
```

Страница показывает токен подключения и кнопку перегенерации. Токен разрешает локальному процессу подключиться к этому профилю браузера. Он именно на профиль: у второго браузера или второго профиля в том же браузере будет свой.

**Шаг 3 — добавить запись MCP-сервера.** В конфигурации MCP вашего агента добавьте по записи на каждый браузер, который хотите иметь под рукой.

**Достаточно одной записи.** Публикация идёт ровно через один браузер, и это должен быть тот, где вы уже залогинены в площадках — это требование 3 из раздела выше, и никаким флагом оно не заменяется. Вторую и третью запись добавляйте только если держите отдельные браузеры под эти аккаунты и хотите выбирать между ними в начале прогона: публикатор тогда сам спросит, какой использовать, до первого действия.

Важны и токен, и `--browser`, и именно второй флаг обычно забывают:

```jsonc
// Оставьте только ту запись (или записи), чей браузер держит ваши залогиненные аккаунты.
"playwright":        { "command": "npx",
                       "args": ["-y", "@playwright/mcp@latest", "--extension", "--browser", "chrome"],
                       "env": { "PLAYWRIGHT_MCP_EXTENSION_TOKEN": "<токен этого профиля Chrome>" } },
"playwright-edge":   { "command": "npx",
                       "args": ["-y", "@playwright/mcp@latest", "--extension", "--browser", "msedge"],
                       "env": { "PLAYWRIGHT_MCP_EXTENSION_TOKEN": "<токен этого профиля Edge>" } },
"playwright-canary": { "command": "npx",
                       "args": ["-y", "@playwright/mcp@latest", "--extension", "--browser", "chrome-canary"],
                       "env": { "PLAYWRIGHT_MCP_EXTENSION_TOKEN": "<токен этого профиля Canary>" } }
```

Имя слева выбираете вы — именно его агент покажет, когда будет спрашивать, какой мост использовать, так что называйте по браузеру, а не по навыку.

`--browser` принимает имя браузера или канал Chrome:

| Значение | Что открывает |
| --- | --- |
| `chrome` | Google Chrome, stable |
| `msedge` | Microsoft Edge, stable |
| `chrome-beta` · `chrome-dev` · `chrome-canary` | соответствующий канал Chrome |
| `msedge-beta` · `msedge-dev` · `msedge-canary` | соответствующий канал Edge |
| `chromium` | обычная сборка Chromium |

`firefox` и `webkit` — допустимые значения `--browser` для Playwright вообще и **не** для этого режима: в собственной справке сервера сказано, что `--extension` подключается к запущенному браузеру, только Edge или Chrome. С такой настройкой прогон просто не подключится.

Остальные форки Chromium — Brave, Vivaldi, Opera, Arc — расширение из того же листинга принимают, но у `--browser` нет значения, которое их называет, а режим расширения документирован как Chrome и Edge. Считайте их неподдерживаемыми для публикации, а не поводом для отладки.

Ещё один флаг, полезный когда в браузере несколько профилей: `--profile-dir-name "Profile 1"` выбирает каталог профиля для подключения. Без него сервер берёт последний использованный профиль, где установлено расширение — обычно это правильный выбор, но его стоит закрепить явно, если аккаунты живут в профиле, которым вы не пользуетесь каждый день.

Без `--browser` сервер открывает свою relay-страницу в браузере по умолчанию. Если обе записи уходят в браузер по умолчанию, та, чей токен принадлежит другому браузеру, будет ждать вечно: стартует чисто, слушает порт, отвечает на `initialize` и не отвечает ни на один вызов инструмента. У этого симптома ровно одна причина, и она здесь.

**Шаг 4 — перезапустить агента**, чтобы он подхватил конфигурацию. Токен, прописанный без перезапуска, выглядит точно так же, как токен, который не сработал.

**Шаг 5 — проверить.** Попросите агента показать список вкладок. Одинокая `connect.html` — здоровое состояние покоя: мост подключён, просто других вкладок нет. Одинокая `about:blank` означает, что вы на чистом запущенном браузере без ваших сессий — вот это отказ.

Когда настроены два моста, публикатор до первого действия спрашивает, какой использовать, затем проверяет движок и залогиненную личность и называет вам и то и другое. Подтвердите, прежде чем разрешить старт.

## Запуск по одному навыку

Каждый навык срабатывает на обычную формулировку. Явное имя делает выбор однозначным.

### Профиль голоса

```text
Используй awesome-content-voice: собери профиль моего голоса из https://myblog.example и постов в ./writing/
```

На выходе один файл профиля. Пишется один раз, переиспользуется всеми последующими запусками.

### Посты из источников о продукте

```text
Используй awesome-content-campaign на этом репозитории и https://myproduct.example — две недели, площадки, где у меня реально есть аккаунты
```

Вас спросят про площадки, период и язык. На выходе — по датированному файлу на пост плюс манифест, в папке, которую навык назовёт.

### Посты из одной готовой статьи

```text
Используй awesome-content-repurpose на https://example.com/my-article — все площадки из таблицы
```

Тот же формат, без расписания. Это тот вариант, который нужен, когда источник — один текст.

### Картинка

```text
Используй awesome-content-graphics для этой кампании: вертикаль 1080x1350, 100 рендеров
```

Вас спросят про look, размер набора, политику заголовков и соотношение сторон. Всё рендерится локально из HTML и CSS — без сервисов генерации изображений, без API-ключей, ничего никуда не загружается. Дальше вы выбираете один рендер по номеру.

### Публикация

```text
Используй awesome-content-publisher на ./my-campaign-folder
```

До первой публикации вы получите: проверку моста, скан источника с жёсткой остановкой на любом дефектном файле, проверку логина по каждой площадке и план прогона, который нужно утвердить. Флаг `--dry-run` показывает весь план, ничего не публикуя.

## Запуск цепочкой

Обычный порядок и что передаётся на каждом шаге:

1. **`awesome-content-voice`** — один раз навсегда. Сохраните файл профиля.
2. **`awesome-content-campaign`** или **`awesome-content-repurpose`** — укажите источник и профиль голоса. Прочитайте черновики. Это момент, когда правят формулировки: все последующие стадии считают эти файлы авторским текстом и не переписывают его.
3. **`awesome-content-graphics`** — берёт факты кампании и отдаёт набор. Выберите один рендер.
4. Добавьте выбранную картинку в файлы постов (пишущий навык делает это сам, если запущен после графики; иначе укажите её во frontmatter).
5. **`awesome-content-publisher`** — укажите папку. Утвердите план прогона. Дайте отработать.

Одна фраза на всю цепочку тоже работает — агент остановится на каждом гейте, где нужен ваш ответ:

```text
Прогони https://example.com/my-article через awesome-content-repurpose, сделай для него графику, потом опубликуй всё через awesome-content-publisher
```

## О чём вас спросят

Гейты существуют потому, что действия публичные, а часть из них необратима. Ожидайте:

- **Какой браузерный мост**, если настроено больше одного.
- **Какие площадки** и что делать с теми, для которых нет файла поста.
- **Просроченные посты**: публиковать сейчас по порядку, пропустить или сдвинуть расписание.
- **Количество хештегов**, если оно расходится с нормой площадки — один общий вопрос с названием площадки, текущим числом, целевым и точным списком добавляемых или снимаемых тегов.
- **План прогона** таблицей, до первого поста.
- **Всё необратимое**: рассылка на Substack, платная аудитория, пост в группу с чужой модерацией.
- **Сабреддит для reddit**, если reddit в наборе — навык не выберет его за вас.

## Сколько это занимает

Замерено на реальном проходе по 25 площадкам, по меткам времени из ledger самого публикатора. Цифра — это полный цикл на площадку: открыть композер, заполнить, приложить картинку, отправить, прочитать пермалинк, сверить с файлом-источником, записать ledger.

| Тип композера | Площадки | На пост |
| --- | --- | --- |
| Простое текстовое поле | x, bluesky, threads, mastodon, truthsocial, minds, peerlist, lemmy, quora, bastyon | 2–6 мин |
| Поле с markdown | devto, wonderful-dev, write-as | 2–4 мин |
| Подпись с обязательной картинкой | instagram, pixelfed, pinterest | 4–8 мин |
| Rich-редактор, короткий пост | tumblr, daily-dev, patreon, ko-fi, buymeacoffee | 3–9 мин |
| Rich-редактор, лонгрид | medium, hashnode, substack, hackernoon, teletype | 4–9 мин |

Цифры по проходу целиком из того же ledger:

- **15 площадок за 73 минуты** непрерывной работы — около 5 минут на каждую, на эту цифру и стоит планировать.
- **Первая площадка сессии стоит дороже**: на неё приходятся гейт моста, преflight-проверки логинов и скан источника. Закладывайте 15–20 минут до выхода первого поста.
- **Графика считается отдельно**: набор из 100 рендеров с геометрическим гейтом и отсевом дублей — это самостоятельная задача, а не часть того часа.
- **Между разными площадками пауз нет.** Два поста на *одну и ту же* площадку разносятся минимум на 2 часа; разные площадки идут подряд.

Что удлиняет проход: композер, чей живой DOM разошёлся с заметками; площадка, потребовавшая ремонтного прохода после сверки с источником; и любой гейт, ждущий вашего ответа.

## Если что-то не работает

**Агент говорит, что браузерным инструментам нужна аутентификация.** Мост настроен и не подключён. Откройте status-страницу в нужном браузере: `No clients are currently connected` подтверждает, что запущенный сервер спарен с другим браузером. Сначала проверьте `--browser`.

**Сервер стартует, отвечает и никогда не завершает вызов инструмента.** Та же причина. Его relay-страница открылась в браузере по умолчанию, где лежит другой токен.

**В списке вкладок только `about:blank`.** Вы на чистом запущенном браузере без ваших сессий. Расширение не подключено.

**В списке вкладок только `connect.html`.** Это норма — собственная relay-страница моста. Не трогайте эту вкладку, прогон откроет свою.

**Токен поменялся.** На status-странице есть кнопка перегенерации. После неё конфиг со старым токеном протухший, пока вы его не обновите и не перезапустите агента.

**Пост опубликовался с неправильным форматированием.** Публикатор сверяет каждый опубликованный пост с файлом-источником и чинит расхождения: правкой там, где площадка её позволяет; удалением и перепубликацией — только в пределах 5 минут и только при нулевой реакции; и прямым сообщением вам там, где площадка не позволяет ни того, ни другого. Если нашли пропущенное — скажите: он переоткроет весь аудит, а не залатает одну названную строку.

## Чего публикатор не делает никогда

- Не вводит пароль, не проходит логин и не заполняет 2FA.
- Не решает и не обходит капчу или проверку на бота.
- Не обращается к API площадки — ни чтобы опубликовать, ни чтобы посчитать посты, ни чтобы выяснить, существует ли что-то. Всё делается так, как делает человек: глядя на страницу и кликая по ней.
- Не удаляет и не редактирует опубликованный пост, кроме как по вашей явной просьбе про конкретный пост.
- Не работает больше чем с одним аккаунтом на площадку и не ведёт аккаунты в масштабе, который площадка запрещает.

Темп публикации — часть того же договора: площадки лимитируют и помечают быстрые скриптовые очереди даже на легитимных аккаунтах, и правила интервалов держат работу внутри обычного профиля использования.
